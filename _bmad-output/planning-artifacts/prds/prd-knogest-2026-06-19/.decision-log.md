# Decision Log

This file is the canonical memory and audit trail for PRD decisions, changes, and overrides.

## Decisions

- **D-001 - Working mode:** Use Fast path because the completed brainstorming already contains extensive product and domain decisions.
- **D-002 - Stakes:** Treat the MVP as an internal pilot intended to validate operational usefulness before broader customer launch.
- **D-003 - Confirmed inputs:** Use `app.md`, the completed brainstorming session, the project-wizard specification, and the canonical cursor-pagination specification. Continue excluding `annot.md`.
- **D-004 - Product intent:** Knogest must be a robust but simple operational ecosystem that helps managers form strategies, allocate resources, and make decisions that improve project performance.
- **D-005 - Pilot scale:** The pilot covers one corporation, no more than three companies, and any number of projects needed to represent the real operation.
- **D-006 - Pilot authority:** The product owner is the sole pilot user and acceptance authority.
- **D-007 - Pilot success:** The pilot succeeds when the administrator can register one complete real operation across the entire brainstorm-defined MVP without inconsistent state or direct database correction.
- **D-008 - Source precedence:** The completed brainstorming decisions supersede conflicting or older scope in `app.md` and the frontend-only wizard specification.
- **D-009 - Landscape research:** Current construction products emphasize connected field/office data, digital daily reports, traceability, resources, and offline mobile operation. This supports the future ecosystem direction but does not expand the pilot MVP.
- **D-010 - Reviewer gate:** The product owner explicitly skipped the optional rubric, adversarial, and edge-case reviewer passes for this internal-pilot PRD.
- **D-011 - Job role:** Employee Allocation job role is required free text in the MVP and is snapshotted in each allocation period. A Company role catalog is deferred.
- **D-012 - Compensation terms:** Employee Allocation compensation mode is one of daily, hourly, weekly, fortnightly, or monthly. Compensation value and overtime rate use BRL with two decimal places.
- **D-013 - Fuel catalog:** The pilot system catalog contains only Diesel S10 and Diesel S500. Project prices use BRL per liter with four decimal places.
- **D-014 - CPF/CNPJ protection:** Mask documents in tables and selectors; show full values only in create, edit, and detail flows for the Master Administrator; exclude documents from logs, tokens, and cursors; encrypt persisted values and use a normalized hash for equality and uniqueness. Preserve documents while operational history requires them. Document purpose, legal basis, and retention before real pilot data entry.
- **D-015 - Session limits:** Access credentials last 15 minutes; refresh idle expiration is 7 days; absolute Session lifetime is 30 days. Refresh credentials rotate on every use in a host-only `Secure`, `HttpOnly`, `SameSite=Lax` cookie. Password reset revokes all User Sessions.
- **D-016 - Historical inspection:** The MVP exposes history in Project, Employee, and Machine detail views. Consolidated historical reports and exports are deferred.
- **D-017 - Wizard size limits:** Defer numeric collection and payload limits to the architecture owner; decide them before implementing FR-26 using the pilot's real resource scale and API performance constraints.
- **D-018 - Finalization:** Source reconciliation and configured editorial passes completed on 2026-06-19. The product owner skipped the reviewer gate, all product-blocking questions were resolved, and the PRD and addendum were marked final.
